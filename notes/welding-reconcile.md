## Welding animation, NPC welders and co-op stations (2026-11-14)
- The game does not invent clips. dist/character.js plays clips stored in the character GLB (about 7: Idle, Walk, Run, Sprint and so on) on the Quaternius armature, plus code on top (IK, grip, lean, crouch, seated, hold(object), a second hand on a handle). A welding clip must therefore be authored on that same armature (same bone names; foot control bones FootL/FootR) or retargeted to it. The owner's Blender mannequin animation is usable only if its rig is the Quaternius armature or is retargeted. The planned character swap (notes/character-swap-design.md) rigs new bodies onto the same armature, so a clip authored on it survives the swap.
- Alternative for the player: build the welding stance in code (lean, hold torch, hand IK to the seam tip), which works at any seam position without a clip. An NPC welder at a station is best as a looping clip at the station anchor (anchor_use / anchor_player_stand).
- Stations as data: each station = a weld table or jig plus its anchors (anchor_ground_tab, anchor_part_slot, anchor_player_stand), a claim flag and a facing. Hall A needs several (proposal: 8) so co-op players and NPC welders each get one; a player claims a free station when starting a task; others see a third-person welding clip and sparks (one shared spark pool). Multiplayer needs a 'working at station N' state in the position message (Opus stage). NPC welders count against the 15 skinned characters (Eden shift at most 6).
