# OPUS-blockedStatic: NPC route table independent of streaming and play state (Opus 5.5)

Fixes notes/eval/reviews/gemini-audit-0.35.17.md finding #1 (and the requested edit at the end of OPUS-wiring.md). The owner authorised edits to dist/world.js and dist/game.js for this task only. I did not touch any other forbidden file and did not run git.

## The bug was real (measured before the change)
I made a scratch probe (scratchpad only, not in the repo). It runs the current dist/*.js game.js in the fake DOM (the same harness as tests/carry-game.mjs) with a saved position, then prints globalThis.__npcRoutes once the warm has finished:
```
spawn                       NPC_ROUTES {"pairs":45,"signature":550110725}
saved at farm   (-60,-230)  NPC_ROUTES {"pairs":45,"signature":1732807849}
saved at forest (80,-262)   NPC_ROUTES {"pairs":45,"signature":1732807849}
```
So two co-op machines (or two saves) could size the schedule blocks differently. OPUS-wiring.md said this was "a co-op safety margin, not a bug seen". That was wrong: the probe there only ever measured spawn. The cause is world.blocked() skipping colliders in chunks that are not loaded (c.off).

## Change
- **dist/world.js** (647 -> 651 lines):
  - createColliders: blocked() and the new blockedAll() now share one scan(x,z,all).
  - blocked() behaves exactly as before (skips !active or off).
  - blockedAll() ignores `off` (streaming). It also counts colliders marked `mutable` as built, even while they are inactive.
  - Marked mutable: choppable tree colliders (felling toggles their active flag) and landmark boxes (setLandmarkVisible toggles theirs).
  - Colliders that are switched off for good (a scene-overlay rebuild sets active=false; remove()) stay off for blockedAll.
  - The world exposes `blockedStatic:(x,z)=>colliders.blockedAll(x,z)`.
  - Comments are updated.
- **dist/game.js** (1765 lines, still CRLF, no BOM; 3 lines edited with single-line Edit anchors):
  - L140 npcStaticBlocked is now `!isWalkableMap(x,z)||world.blockedStatic(x,z)||colliders.some(b=>!b.door&&...)`.
  - L386: the shop door blocker gets `door:true`.
  - L138: the comment is updated.
  - Why the game `colliders.some(...)` stays: game.js's own `colliders` array (building shells, box() solids, oak trunks, parked cars, the parcel locker, doorway back walls) is NOT in the world's collider hash, so world.blockedStatic cannot cover it. Its only mutable entries are the two shop door blockers, which updateDoors splices in and out. These are now skipped.
  - Skipping the door blockers is safe: the doorway back wall stays, so the doorway is a dead end at the threshold, never a shortcut.
- **tests/npc-static-blocked.mjs** (new, 41 lines). It covers:
  - The collider list alone: c.off ignored, a mutable inactive collider still blocks, an overlay box switched off for good does not block, a removed collider does not block, and the player radius is kept.
  - The real world: 71,883 sample points (spawn, farm, forest, every landmark) give identical blockedStatic answers in each of these cases:
    - only the spawn chunks loaded
    - farm and forest chunks loaded
    - 395 trees felled and 57 landmarks hidden
    - compared with the blocked() of an unstreamed world
  - Each case also asserts that blocked() itself DID change, so the probe would see a difference if there were one.
- PROJECT-INDEX.md was regenerated by `npm run index`. The packaged release dist/releases/0.35.17 was rebuilt with --force.

## What I could NOT verify
- Nothing was seen in a browser. NPC walking was not watched; this changes only the route LENGTH table measured at the menu.
- After the warm, pacing and late routes still use worldBlocked (streamed). That is unchanged and outside this stage.
- No two real co-op machines were compared. The equality is shown by the probe (different saved positions, felled trees) and by the test.
- Measured cost of blockedAll: the same bucket scan as blocked(), so the menu warm cost should not change. I did not time it separately.
- dist/releases/0.35.17 was rebuilt with --force while the owner is play-testing it, as instructed. A browser tab that is already open keeps the old files until it is reloaded.

## Confidence
- blockedStatic ignores streaming and felling/landmark state: high (unit test and in-game probe).
- The schedule signature is the same at spawn, farm, forest and with felled trees: high (measured in the real game loop in the fake DOM).
- No change to play collisions (blocked() logic is the same; npm test is all green): high.
- Door handling choice (skip the blocker rather than always count it): medium-high. It is deterministic either way, and a closed-door variant would only change lengths if an NPC destination sits inside a doorway.
